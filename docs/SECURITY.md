# Execution and privacy

Compilation and execution of program sources occur only inside disposable Docker containers. If Docker or the image is unavailable, the execution path stops. There is no host-execution switch. The UI itself is bound to localhost and is intended for a trusted single user, not an internet-facing service.

Containers run as UID/GID 65534, with a read-only root filesystem, no network, all capabilities dropped, no-new-privileges, Docker's default seccomp policy, a PID limit, CPU quota, memory/swap cap, bounded tmpfs filesystems and resource limits. The only host mount is a temporary read-only directory containing one C file and common.h. No home folder, experiment repository, API key or Docker socket is mounted into a worker. The controller receives its job on stdin and protects its memory with PR_SET_DUMPABLE=0; expected outputs are not placed in files accessible to the program. Each executed child has bounded stdout/stderr, a wall-time limit and its own process group. Timeout handling kills descendants; the host also forcibly removes a leftover container. Files are cleaned up on normal exits and exceptions.

Docker is a shared-kernel boundary, not a guarantee against all hostile native-code exploits. This is a local research tool. For adversarial public submissions use a dedicated disposable VM or stronger hardened sandbox, a job queue, authentication and independent security review. Do not mount private folders, use privileged mode, expose the dashboard publicly or disable sandbox protections. A valid output could still be produced by a dishonest hardcoded implementation; randomized held-out cases and source review are needed for research integrity.

Secrets are read from local .env or the session-only password field. They are not sent to compilation containers, stored in experiment configuration or included in exports. API exceptions are sanitized; HTTP response bodies/headers are not logged. Remote API base URLs must use HTTPS; localhost HTTP is allowed for a local model. Redirects are rejected. Source transfer is an explicit UI/CLI configuration choice and every AI request is announced in the run log. The user is responsible for choosing the provider and model. Provider text/source may itself contain confidential information, so experiment files should be treated as private.

Source input is UTF-8, limited to 256 KB and copied under a fixed filename. User filenames are not interpolated into shell commands. CLI subprocesses use argument arrays, not shell=True. This is not an antivirus scanner or a guarantee that generated algorithms are correct.
